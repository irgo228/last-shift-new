# Последняя смена · MINI (3 вопроса)

Отдельный интернет-сайт на Next.js 15 + Supabase. Только HTTP: никаких SSE, WebSocket, фоновых серверных таймеров, локального file backend и кода большой игры B13/B14.

## Что реализовано

- 8 исходных изображений извлечены из предоставленного Word-документа без перерисовки.
- Титульный экран с местом под действующий QR-код и кнопку старта.
- Пароль и подписанная HttpOnly cookie ведущего; роли проверяются сервером.
- Комнаты с четырёхзначным кодом, максимум 15 участников, атомарное присоединение через Supabase RPC.
- Три заранее встроенных вопроса, 30 секунд + 10 секунд демонстрации ответа.
- Ответ записывается только один раз и только в пределах разрешённого времени по часам PostgreSQL.
- Последовательность фаз вычисляется из `started_at`: продолжение игры не зависит от таймеров серверного процесса.
- Рейтинг: +1 за правильный ответ; при равенстве — суммарное время правильных ответов по серверным меткам.
- Автоматическое имя победителя и ТОП-10 поверх готовой фоновой картинки.
- Участник восстанавливается после перезагрузки из сохранённого на своём устройстве секретного токена.

## Необходимая настройка **интернет-версии**

1. Создать отдельный проект Supabase (не переиспользовать БД большой игры). В SQL Editor один раз выполнить `supabase/001_mini_quiz.sql`. Supabase service-role ключ не должен попадать в браузер.
2. Разместить этот репозиторий в GitHub. Подключить репозиторий к Tatnet Apps (Next.js/Node 22; проверить актуальный поддерживаемый формат сборки и запуск в настройках Tatnet).
3. Указать в настройках переменных окружения Tatnet (см. `.env.example`):
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY` (только на сервере)
   - `HOST_ACCESS_PASSWORD` (от 12 символов)
   - `HOST_SESSION_SECRET` (случайная строка от 32 символов)
   - `PUBLIC_SITE_URL` необязателен; QR формируется в браузере по фактическому публичному URL.
4. Установить зависимости и выполнить `npm run build`. Запуск `npm run start` или штатный способ Tatnet.
5. Открыть публичный URL на Tatnet, проверить `/api/health`, войти в `/host`, создать комнату и подключиться с телефона по QR.

**В этом пакете нет секретов, настроенной удалённой БД или ссылки на опубликованный Tatnet.** Пакет не является доказательством успешного развёртывания.

## Работа

Host: `/host` → пароль → создать комнату → QR и код → начать → вопросы → финал. Player: сканировать QR → имя → ответить. После игры Host нажимает «Новая комната».

## Расписание

Начало фиксируется на сервере в Supabase. С момента `started_at`: вопрос №1 [0–30с], разбор [30–40с], вопрос №2 [40–70с], разбор [70–80с], вопрос №3 [80–110с], разбор [110–120с], затем финал. Это **две минуты игрового процесса**, подключение и поздравление занимают дополнительное время.

## Изображения

Файлы `public/assets/*` извлечены без изменения содержания из «Сайт викторина(1).docx». Исходное разрешение схем — 1427–1724 пикселя по ширине, титульного и финального фонов — 1431×806. **Из Word невозможно получить больше деталей, чем есть во вложенных файлах.** Если на проекторе схемы нечёткие, заменить файлы одноимёнными оригинальными PNG/JPEG.

## Контроль перед мероприятием

После деплоя выполнить пробную комнату с 15 реальными телефонами, проверить одновременные ответы, переключение Wi-Fi/сотовой сети, восстановление после refresh, 30/10-секундные фазы и ТОП-10. Локальные unit-тесты не заменяют физический Tatnet PASS.

## Безопасность

- Никаких Supabase ключей и пароля Host в `NEXT_PUBLIC_*`, коде или GitHub.
- SQL RLS включён, а RPC разрешены только серверной роли.
- Не выкладывать `.env` в GitHub.
- Не использовать производственную базу старой игры.

## Доступные команды

`npm run test` — тестирование чистой логики. `npm run check:assets` — проверка 8 изображений. `npm run build` — Next.js production build (требует установки зависимостей).
